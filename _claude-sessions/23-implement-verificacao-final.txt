  Follow-ups found during the phase (not fixed)

  The full notes for each step are in docs/phases/phase-03-videos/progress.md.
  The main items:

  - Empty request schemas in openapi.json: the export script runs without the
    Swagger CLI plugin, so request bodies such as InitiateUploadDto and the
    Phase 02 auth inputs show no fields.
  - Worker exits with code 1 on docker compose stop: npm reports the SIGTERM as
    a failure. A possible fix is to run the Nest CLI directly with init: true in
    Compose.
  - Shared dist/ folder: a build inside nestjs-api wipes the folder the worker
    runs from, which can make the worker restart once.
  - Leftover files after a failed cleanup: if the storage cleanup for an
    abandoned draft fails after the database update, the next run won't retry
    it. Files left under videos/{id}/ stay in storage.
  - Changing the part size breaks open uploads: the number of parts is
    recalculated from UPLOAD_PART_SIZE_BYTES. Changing that value while uploads
    are open changes their part layout.
  - 500 errors with no error code:
    - a user who has no channel tries to upload;
    - storage and database disagree when an upload is completed;
    - ffmpeg can't extract any frame, which ends as processing_failed instead of
      invalid_media.
  - Existing warnings:
    - npm audit advisories;
    - pg "client.query() when the client is already executing a query"
      deprecation warnings during tests;
    - Node's --localstorage-file warning.

  Committing and opening the PR are up to you. The branch is
  feature/phase-03-videos.
